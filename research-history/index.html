Menu Lens research archive

設計演進與失敗方向

一份可閱讀、可操作的研究時間線。它必須清楚區分當時真正執行過的原始介面、後來為比較而重建的說明性版本，以及尚未驗證的新假設。

6 個時期 原始實作與重建分開標示 同一份 reference menu 非正式產品介面

Evidence types

先看清楚：不是每個 HTML 都是歷史原件

原始實作必須能連回當時的 branch、PR 與固定 commit。說明性重建只能幫助理解流程，不能取代當時真實的版面、操作與程式。新原型則只代表後來提出的假設。

Original implementation

直接來自當時實際執行的 source 或 build，附固定 PR 與 commit。這才是歷史畫面本身。

Interpretive reconstruction

後來為了說明或比較而重做。可以保留，但必須明寫「重建」，不得冒充原始畫面。

New hypothesis

當時沒有可執行 HTML，後來才提出或補做。它是研究中的新證據，不是歷史復原。

Timeline

從長菜單，到決策工作流，再回到閱讀尺度

每個階段都要同時回答兩件事：它處理了什麼，以及目前可點的畫面到底是原始實作、後來重建，還是新假設。

Archive rules

接下來怎麼修正

原始版本優先

01 直接開 PR #3 原版。02–04 將從 PR #4 歷史 commit 與 final build 凍結，不再以手刻重建取代。

重建仍可保留

目前的簡化版可作為流程教學與 A/B 任務材料，但必須永久帶有 reconstruction 標籤。

來源必須可追溯

每個原始快照都要記錄 PR、branch、固定 commit、build 方法與是否包含後續功能。
