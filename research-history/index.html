How to read

先看物件性質，再看研究家族

同一個家族內可能同時存在 substrate、controlled keep、provisional、negative evidence 與 study。物件狀態描述它在研究中的處置，不等於正式使用者研究結論。

Object catalog

一個 ID，就是一個可追溯研究物件

Catalog v2 將物件類型、研究處置與證據狀態拆開。既有 prototype registry 暫時保留為 migration source，首頁不再維護第二份手寫物件清單。

目前沒有符合篩選條件的研究物件。

Original implementations

固定 commit 的歷史原件

原始輸出由 manifest 產生，不與後續 reconstruction 或 prototype 混在同一種來源標籤裡。

Migration boundary

這一階段只整理控制層

現有 prototype UI、研究資料、入口 URL 與歷史快照都保持不變。後續家族入庫會在 catalog 中新增 prototype、correction、study 與 negative evidence，而不再手改首頁卡片與比較表。
